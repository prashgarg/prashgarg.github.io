# Website review — prashgarg.github.io (2026-06-15)

Multi-dimension, adversarially-verified review. 12 dimensions → 88 candidate
findings → **84 confirmed** (4 refuted in verification): **6 High, 28 Medium,
45 Low, 5 nits**. No criticals. Duplicates across dimensions are consolidated
below; the parenthetical IDs (H#, M#) trace back to the raw findings.

## Executive summary

The site is a beautiful, technically accomplished 3D experience — and that is
exactly its central risk. For an academic whose goal is *to be found, read, and
contacted*, the novelty currently sits **in front of** the content: a cold visitor
stares at a near-black screen for ~7.5–8.6 s before the START control even
appears, the homepage (the URL Google ranks for "Prashant Garg") ships **zero
crawlable text or links**, and the one page that is perfect for a hurried
recruiter — `/standard` — is undiscoverable from the home page. None of these are
hard to fix; most of the highest-impact items are one-line or one-component
changes. The single best lever is to **decouple a fast, content-bearing entry
from the heavy 3D payload** so the experience is additive rather than gating.

**Top 3 to do first:** (1) fix the `robots.txt` sitemap line — it points crawlers
at the dead old domain; (2) make a content/skip path paint instantly (SSR splash +
crawlable homepage links + a visible "Plain version" link to `/standard`);
(3) correct the "LSE" affiliation on the boot splash, which the data doesn't
support.

## HIGH (6)

**1. Cold load shows a near-black screen for ~7.5–8.6 s before any content or START** — `index.astro` / `Three.astro` (H6)
`Office` mounts `client:only="react"`, so nothing renders server-side; the 1.1 MB
Office bundle + 184 KB React client + ~1.9 MB textures must download/parse/hydrate
before the BIOS splash even appears. Live: first BIOS text at 7560 ms, START at
8610 ms. An impatient visitor sees a blank page and leaves.
*Fix:* render the BIOS/START splash as static SSR HTML (it's pure DOM, no 3D) so it
paints on first byte; lazy-load the 3D bundle only after START; defer texture
downloads until after "idle".

**2. Homepage ships no crawlable content and no links; no-JS/screen-reader users trapped** — `index.astro`, `Office.tsx:3748-3771` (H4 + M10)
`dist/index.html` body is just the text "loading the library…" — zero `<a href>`,
no name/affiliation text. All links (to `/research`, `/standard`, …) are built only
inside the client-only React no-WebGL branch, so they never reach static HTML. The
canonical root passes no link equity and exposes no author text; non-JS crawlers
and screen readers find no path in.
*Fix:* server-render a `<noscript>`/visually-hidden block with `site.bio` and anchor
links to the inner pages + `/standard`, independent of hydration.

**3. `robots.txt` sends crawlers to a sitemap on the dead old domain (404 live)** — `public/robots.txt:4` (H1 + M4 + M16 — flagged by 3 dimensions)
`Sitemap: https://www.prashantgarg.org/sitemap-index.xml`. That host still serves
the old Google Site; curled live it 404s, while `prashgarg.github.io/sitemap-index.xml`
→ 200. Any crawler obeying robots.txt never finds the real sitemap. Every *other*
absolute URL correctly uses github.io — only this line leaked the old domain.
*Fix:* change the line to the github.io sitemap; better, derive it from `site.origin`
at build so it can't drift. Flip with `astro.config` + `site.ts` at DNS cutover.

**4. Boot splash + Study scene claim an "LSE" affiliation unsupported by the data** — `Office.tsx:3127` (also `Study.tsx:907`) (H5)
The BIOS splash subtitle reads `Economist · Cambridge · Imperial · LSE` (baked into
the shipped bundle). But `site.ts` affiliations list only Cambridge (Research
Associate), INET Oxford (Associate Fellow), Imperial (PhD), incoming Bocconi
(Postdoc). LSE appears only as a press outlet / conference venue — not an
affiliation. Reads as overstating the record and contradicts every other surface.
*Fix:* replace "LSE" (e.g. `Cambridge · Oxford · Imperial` or `… · Bocconi`), and
drive the byline from `affiliations[]` so the splash and CV can't drift.

**5. `<Environment preset="lobby">` hotlinks a 1.5 MB HDR from a third-party CDN on the critical path** — `Office.tsx:2461` (H2)
drei resolves the preset to `st_fagans_interior_1k.hdr` on `raw.githack.com`
(baked into the prod bundle). It's a 1.5 MB off-origin asset *not counted in the
11 MB dist*, on the scene's lighting critical path, depending on a free hotlink
service that rate-limits and isn't for production. If it fails, every glossy
surface goes flat.
*Fix:* self-host the HDR in `public/` (`<Environment files="/hdri/lobby.hdr">`),
ideally a compressed 512px version — or drop the preset and bake the small IBL
contribution into the existing ambient/hemisphere lights.

**6. `prefers-reduced-motion` is ignored across the 3D scene** — `Office.tsx:770-860; 3255-3276` (H3) — WCAG 2.3.3
No `matchMedia` for reduced-motion anywhere. Camera dolly, boot typing, HUD
typewriter, postprocessing, and the pulsing hint all run unconditionally.
*Fix:* gate animations on `prefers-reduced-motion` — jump the camera to its end
pose, render text instantly. (Note: a BIOS "Reduced motion" toggle exists in Setup
but is dead config — wire it in too.)

## MEDIUM (28, consolidated)

**Performance**
- **Office.js is one 1.1 MB chunk (303 KB gzip), no internal code-splitting** (M9). three+drei+postprocessing+InnerDesktop all eager-loaded; combined critical path ≈3.6 MB. GH Pages serves gzip but not brotli. *Fix:* `React.lazy`/dynamic-import the postprocessing + OfficeScene so the splash + React glue ship first and 3D streams in during the BIOS read.
- **1.8 MB of uncompressed 1K JPG PBR textures load on the home page** (M8). Carpet/Wood normal maps are 632 KB / 523 KB each, served `max-age=600`. *Fix:* downscale to 512px and/or re-encode WebP; consider dropping the 268 KB carpet AO map.

**SEO / metadata**
- **No `schema.org/Person` JSON-LD anywhere** (M17). The highest-value structured data for an academic (knowledge panel, Scholar linkage) is absent; only per-paper `ScholarlyArticle` exists. *Fix:* add a Person block to the homepage + `/standard` from `site.ts` (name, jobTitle, affiliation, alumniOf, `sameAs`:[scholar, github, twitter, bluesky]).
- **Inner pages share one identical meta description** (M18). `/research`, `/talks`, `/library`, `/now` inherit the site tagline byte-for-byte. *Fix:* pass distinct descriptions (the OG route already has good per-page strings — reuse them).
- **`/cv` references a non-existent OG image — `/og/cv.png` 404s live** (M2 + M19). The OG route never defines a `cv` entry, so the CV page (likely shared by committees/journalists) unfurls with a broken card. *Fix:* add `cv` (and `standard`) to the `pages` map in `og/[...route].ts`, or fall back to `/og/index.png`.
- **`/standard` — the crawler/recruiter-perfect page — has no OG/Twitter cards and is unreachable from the homepage HTML** (M20 + M12 + M23). It's a clean sub-1s server-rendered academic page, but the only ways in are the Start menu (after the slow boot) or the no-WebGL branch; nothing static links it, and it emits zero `og:`/`twitter:` meta. *Fix:* add OG meta to `standard.astro`; surface a "Plain text version / Skip intro" link on the BIOS splash + a static homepage link.

**Content accuracy**
- **Atom feed stamps the not-yet-published "Forthcoming" paper with the current year** (M21). Papers without a `year` fall back to `new Date().getFullYear()` → `2026-01-01` `<published>`/`<updated>`, asserting publication dates for forthcoming/working papers. *Fix:* only emit `<published>` for genuinely published items; use the build date for `<updated>`.

**UX**
- **Deep-link / returning-visitor parks the camera at the far doorway and slow-creeps to the monitor** (M1 — this confirms & root-causes the `?app=` framing oddity I flagged earlier). Phase inits to `'desktop'` but the camera default is the doorway, and the desktop branch only does an 8%/frame lerp (no eased dolly). Live: the iframe grew 56→152→302 px over ~10 s. *Fix:* when phase initializes to `'desktop'`, pre-position the camera at `CAM_COMPOSITE_POS` before the first frame (or run the eased dolly once).
- **No visible cue that clicking the room exits the desktop** (M22). Entry has a pulsing "click monitor" hint; there's no symmetric exit cue, so zoomed-in readers can feel trapped. *Fix:* add a quiet persistent "Click the room to step out · Esc" chip while in composite-desktop, and wire window-level Escape to exit.

**Accessibility cluster** (M11–M15)
- No keyboard path into the 3D desktop (mouse-only mesh click; canvas has no role/aria-label) (M11).
- Win95 desktop icons and Start items are non-operable `div`s (no role/tabIndex/keydown) (M13).
- Tray + HUD mute buttons are `mousedown`-only, so keyboard can't mute auto-playing audio (WCAG 1.4.2) (M14).
- Muted text classes (`text-ink/40–55`, `text-cream/40`) fail WCAG 1.4.3 contrast (2.5–3.9:1) on real content (M15).
- `/standard` undiscoverable without mouse + WebGL (M12).

**Build / repo hygiene**
- **645 screenshots tracked in git — working tree ~292 MB, `.git` 522 MB** (M5). Throwaway audit PNGs; every clone pulls half a gigabyte. *Fix:* `shots/` → `.gitignore` + `git rm -r --cached shots/`; optionally `git filter-repo` to reclaim history (coordinate — rewrites SHAs).
- **No `prebuild` Node guard** (M6). `predev` guards the version but `npm run build` on Node 23+ hangs silently. *Fix:* add `"prebuild": "node scripts/check-node.mjs"`.

**Dead code & dead assets** (M3, M7, M24, M25, M26)
- `Room.tsx` (1,154 lines) and `Study.tsx` (1,561 lines) are imported by nothing — cottage/study-era predecessors of `Office.tsx`.
- The ~1 MB of cottage/garden `.glb` models (`tree.glb` 299 KB, etc.) are consumed only by dead `Room.tsx`, yet ship to `dist/` and are publicly reachable (verified 200 live). Pure dead weight. (`textures/` is NOT dead — keep it.)
- `Layout.astro` / `Nav.astro` / `Footer.astro` are dead too (every page uses `Win95Layout.astro`), and **CLAUDE.md is wrong** — it says inner pages use `Layout.astro` with a "← Outside" nav that doesn't ship. *Fix:* delete the dead components + `public/models/`, and correct CLAUDE.md.

**Maintainability**
- **`Office.tsx` is a 3,846-line monolith** (~50 components across 5+ concerns) (M27). *Fix:* extract into `src/components/office/` (ui-audio, ambient-audio, camera, overlays, props, scene) leaving a thin state-machine shell — after deleting `Study.tsx`.
- **UI-audio helpers + `getTime()` copy-pasted across Office/InnerDesktop/Study and already diverging** (M28). *Fix:* extract `src/lib/ui-audio.ts` + `src/lib/format.ts`.

## LOW (45, grouped)

**Window system (`InnerDesktop.tsx`)**
- Two windows opened in one render tick get duplicate z-index (use a functional `setTopZ` updater).
- JS resize min (360×260) < CSS min (520×360) → resize handles detach from the window edge.
- Drag y-clamp ignores the 30 px taskbar → a title bar can hide behind it.
- Windows open at ~90% of the desktop, so a buried window's title bar is unclickable (smaller default or bigger cascade).
- Dead per-app `defW`/`defH` config (never read by `defaultGeo`); dead `muted`/`setMuted`/`audioRef` state.
- Modal dialogs (Run / System Properties / Wellness) don't trap focus.
- Search: `Cmd+K` only works once an inner-page iframe is focused — unavailable on the bare desktop.

**SEO / routing**
- No Atom feed autodiscovery `<link>` in any head — `/papers.xml` is hidden.
- `/os` is in the sitemap despite being `noindex` (add a sitemap `filter`).
- BibTeX keys collide — two papers both emit `@misc{gargai,…}` (include the slug/year).
- Sitemap URLs have trailing slashes but canonical/og:url/JSON-LD don't — pick one form.
- Incomplete OG/Twitter cards (no `twitter:site`/`creator`, `og:site_name`, `og:image:alt`/dimensions).
- Home page (`Three.astro`) ships thinner meta + a generic description than inner pages.

**Performance**
- `frameloop="always"` re-renders the whole scene + bloom continuously while the user reads inside the (static) composite monitor — switch to `'demand'` for `phase==='desktop'`.
- `GrainOverlay` regenerates a noise canvas via `setInterval` forever (allocates ImageData each ~66 ms) even when invisible behind the iframe.
- `ambient.mp3` (2.0 MB) fetched whole on first pointerdown (consider a shorter/lower-bitrate loop).
- No instancing for repeated geometry (only matters if frame-rate dips appear).

**Responsive / cross-browser**
- `viewport` meta missing `initial-scale=1` on every layout except `standard.astro`.
- `CameraRig` FOV breakpoints don't match the documented 58/50/42/36 (real: 50/54/56) — fix code or docs.
- Pointer-equipped iPads fall into the heavy desktop composite path (consider `(any-pointer: coarse)`).
- Window drag is mouse-event-only (fine for phones; switch to Pointer Events if hybrid tablets matter).
- `screenshot.mjs` can't reach the touch/mobile code path (add a `--mobile` device mode).

**3D robustness**
- No graceful fallback if the composite `/os` iframe fails to load — blank teal rectangle, only escape is the undocumented click-outside (add `onError`/timeout with links).

**Content**
- Two divergent CV sources (Drive link in `site.cv` vs local `/cv.pdf`) risk serving a stale CV — pick one canonical URL.
- Placeholder "TBC" talk title is live on Talks + CV.
- Dead `Footer.astro` still points at the Drive CV.

**Security / privacy** (proportionate — static site)
- Google Fonts third-party origin leaks visitor IP/UA on every page — self-host or use fontsource.
- Plain un-obfuscated `mailto` in built HTML (accept or obfuscate).
- `postMessage` `pg-shutdown` handlers omit an origin check (low impact; add `e.origin === location.origin`).
- No CSP/referrer meta — add `<meta name="referrer" content="strict-origin-when-cross-origin">` to shared layouts.
- `npm audit`: ~5–8 high advisories, all in the build-time esbuild/vite/astro chain (no non-breaking fix; do **not** `npm audit fix --force` — it downgrades Astro). Track upstream.

**Maintainability**
- sessionStorage keys + the postMessage contract are stringly-typed across 4 files — centralize in `src/data/os-contract.ts`.
- Three unused deps (`pagefind`, `astro-pagefind`, `canvaskit-wasm`) — remove or actually integrate search.
- ~20 undocumented one-off `review-`/`probe-`/`verify-` scripts — prune (git keeps history).
- `public/models/README.md` + README describe the deleted cottage scene as the live home.
- Nine `eslint-disable(exhaustive-deps)` escapes with no rationale.
